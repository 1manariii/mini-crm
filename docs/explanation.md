# Как устроена система — объяснение для руководителя

**Что это.** Простая рабочая тетрадь компании в интернете. В ней два списка:
объекты (стройки) и задачи по ним. Вход — по email и паролю, самому зарегистрироваться
нельзя: учётные записи выдаёт администратор.

**Кто что делает.** В системе две роли.

- *Постановщик* — руководитель. Создаёт объекты и задачи, назначает исполнителей,
  принимает выполненную работу или возвращает её на доработку с обязательным комментарием.
  Видит всё.
- *Исполнитель* — работник. Видит только свои задачи и те объекты, где у него есть задачи.
  Чужие задачи ему недоступны совсем. Он может взять задачу в работу и отправить её
  на проверку. Больше ничего: ни создать, ни удалить, ни поменять чужое, ни одобрить
  свою работу самостоятельно он не может.

**Жизнь задачи.** Каждая задача движется по понятному кругу:
«Новая» → «В работе» → «На проверке» → «Принята». Если работа не устроила,
постановщик возвращает её «На доработку» — и обязательно пишет, что не так.
Круг повторяется, пока задачу не примут. Перепрыгнуть через шаг или пойти
в обратную сторону нельзя: в интерфейсе у каждого пользователя видны только те кнопки,
которые ему доступны прямо сейчас.

**История.** У каждой задачи есть история: кто, когда и какой статус поставил
и с каким комментарием. Эту историю нельзя отредактировать или удалить —
так всегда можно восстановить, кто и когда принял решение.

**Как защищены данные.** Главное: ограничения работают не только «на кнопках»
в интерфейсе. Они продублированы в самой базе данных — хранилище само проверяет
каждый запрос. Даже если кто-то обойдёт сайт и обратится к хранилищу напрямую,
исполнитель не прочитает чужую задачу, не сменит статус, который ему не положен,
и не подделает историю. Ключей, дающих полный доступ к базе, на сайте нет —
они хранятся только у администратора.
